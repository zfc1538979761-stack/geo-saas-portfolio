## 90 秒面试介绍

这个项目是一个面向企业内容运营的 GEO SaaS。负责人先提供了初步需求、开发参考资料和一些业务思路，我在这些输入的基础上独立完成系统开发与落地，包括前后端业务、数据库、API 接入、调试和测试交付。公司提供上游 API，项目侧如何适配接口结果，以及如何与内容、订单和账务关联，由我实现。底层使用 FastAdmin 和 ThinkPHP，并借助 AI 工具辅助开发。

产品流程从企业资料和知识开始，生成并审核用户问题，再确认带来源的目标答案，生成可追溯的文章版本。之后选择媒体、确认报价、创建发布订单，并处理状态同步和余额变化。GEO 部分建立发布前 Baseline、发布后复检计划、趋势和优化建议，供下一轮内容调整使用。

我重点处理了几个问题：异步任务重复执行如何避免生成多份结果，文章编辑与版本如何追溯，重复订单状态如何避免重复扣款，以及不同企业的数据如何隔离。求职展示版使用虚构数据和本地 Mock 服务，模拟可见度结果明确标注，不把演示趋势当作真实推广效果。

## 面试追问：可直接参考

### 负责人参与了哪些工作？

负责人提供项目方向、初步需求、开发参考资料和业务思路，具体的系统开发、接口对接、调试和落地由我完成。因此我将自己的角色表述为“独立开发与实施”，并保留负责人在需求和方向上的贡献。

### API 是公司提供的，你具体做了什么？

公司提供的是上游接口资源。我完成的是系统侧接入，包括请求与响应适配、鉴权配置、字段和状态映射、错误处理，再把接口结果接到任务、文章版本、发布订单和账务流程里。底层模型或外部媒体服务由上游提供；负责人提供项目方向和业务思路，我负责系统开发、接口集成和业务流程实现。

### 这个项目是不是只做了一个 API 调用页面？

项目除接口调用外，还包括企业资料和知识、问题审核、目标答案、文章版本、异步任务、媒体筛选、发布状态、余额流水和租户隔离。我可以用任务记录、文章历史版本、订单时间线和数据结构解释这些模块如何关联。

### 使用 AI 辅助开发，怎么说明个人贡献？

我会如实说明使用了 AI 工具。负责人提供初步需求和业务思路，我独立负责开发实施与交付，包括将需求落实为功能、接入接口、推进开发迭代和完成验证。具体面试时，我会选自己能够解释清楚的模块，结合代码和运行结果说明设计、问题与处理方式，不将 AI 生成的代码描述成逐行手写。

### 做出了什么成果？

完成了一套具有资料、内容、订单、账务和 GEO 跟踪模块的 SaaS 业务系统，并整理了可本地运行、可复现的脱敏演示版。Portfolio 的测试和截图可以证明演示实现；真实业务效果需要另外的真实记录，当前不添加客户、营收或 AI 收录增长数字。
