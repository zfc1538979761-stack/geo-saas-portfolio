# 技术架构与三个实现案例

企业工作台通过 API 访问领域服务；企业身份生成可信 TenantContext，数据网关附加 company_id。订单/账务服务还在 SQL 边界显式限定企业。数据库保存任务、版本、订单及流水事实；Redis 只承担调度。

## 异步内容生成
输入快照固定企业资料、知识、问题、精确提示词和目标答案版本。任务通过原子认领、幂等键和版本校验避免重复生成及覆盖并发编辑。Worker 失败可按策略重试，调用记录关联文章版本。本版 Provider 只产生本地可重复结果。

## 发布状态与资金联动
先报价并检查价格指纹，再冻结演示余额。状态机限制合法迁移，published 对应 capture、rejected/cancelled 对应 release。流水以业务幂等键防重复处理。外部请求不放在长数据库事务中；异常进入可恢复状态。本版供应商完全模拟。

## Baseline 与租户证据
Baseline 关联问题、平台、模型和分类版本，必须早于订单首次 published 事件。复检不能用发布后结果补造基线。目标答案保存逐字证据和来源快照，跨企业资源统一不可见。趋势只解释当前模拟回答分类，不推导真实营销因果。

本版使用模块化单体，无微服务、向量检索或生产联网检测声明。
